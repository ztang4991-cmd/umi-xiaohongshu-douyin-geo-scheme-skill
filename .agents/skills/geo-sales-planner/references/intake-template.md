## 使用说明

**填写节奏**

- 引导式问答结束后立即填写；主问题或方案方向发生变化时同步更新。
- 进入方案制作前，由销售确认第 1-3 项（原始请求、真实问题、已确认事实）；其余各项可在过程中补充。

**各字段说明**

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| 原始请求 | ✓ | 原话或最接近复述，不加解读 |
| 真实问题 | ✓ | 决策/行动目标，通常比"做方案"更具体 |
| 已确认事实 | ✓ | 有来源可查的信息；数字必须标注时间点和口径 |
| 未验证假设 | ✓ | 列出越多越好；方案执行中逐一核销 |
| 关键变量 | ✓ | 变了就要重写方案的那几个 |
| 当前主问题 | ✓ | 限一句话，包含"对谁/何场景/何机制/何结果"四要素 |
| 交付物与验收 | ✓ | 明确格式、受众、使用场合和验收标准 |
| 面谈确认项 | ✓ | 清单式；签约前逐项打勾 |

**证据级别标注规范**（与 team-profile.md 保持一致）

- `[公开抽样·日期]`：特定时间点、特定账号状态下的单次观察，不代表固定排名或长期数据
- `[客户提供·未核实]`：数字或资料来自客户陈述，尚未交叉核验
- `[现场核实·日期]`：已通过线下或多源交叉确认
- `[待核实]`：目前仅作假设使用，须在面谈或启动后确认

**不写什么**

- 不在此文件里写具体方案内容或选题计划
- 不写无法核实的效果承诺（"能带来 50 个线索"）
- 不写客户隐私信息（手机号、内部报价、签约金额）
